# ATLAS development privacy disclosure

ATLAS's current development extension communicates with a separately user-run local companion at `127.0.0.1:17892`. Local file contents are read only within folders the user explicitly grants. File operations are performed by that companion under the user's operating-system account, and writable grants are separate from read-only grants.

The companion retains folder-grant metadata, paired-extension credential digests, a private native bootstrap key and mutation receipts in a private local state directory. Catalog data can retain file locators, bookmark URLs, names, tags, notes and relationships. Such metadata may be sensitive even when file bytes are not copied. The browser stores its pairing token in extension session storage. Never include a token, private state database or personal catalog export in public bug reports.

This development slice has no analytics backend, advertising, telemetry or mandatory cloud account. Its extension host permission is restricted to the loopback companion; `storage` retains pairing state, `sidePanel` provides the optional Chrome panel, and `nativeMessaging` connects only to a separately user-installed exact-origin native host for authenticated helper wake/pairing. It has no content scripts or permissions to read arbitrary web pages. If bookmark integration is enabled in a later revision, Chrome's corresponding permission and a revised disclosure are required. R2 and other cloud connectors require separate consent and their own data-handling description before use.

Revoke native grants or pairing using the companion's local CLI. Stop the companion to end access through its process. Removing the extension removes its browser-managed extension storage but does not uninstall a separately installed companion or delete native state/catalog files. To remove native data, stop the companion, inspect and explicitly delete the chosen state directory and any catalog exports. Files in granted folders belong to the user; deleting companion state must not delete those files. Files intentionally moved to local recovery staging remain in the granted folder until separately restored or removed with user consent.

This is a description of a development build, not an independent privacy/security audit or an approved Chrome Web Store listing. Release distributions need published support details, final permissions review, installer/uninstall verification, secure update policy and review of every subsequently added provider.
