# Rich real-world tagging — implemented candidate, not promoted release

Recorded 2026-10-19 UTC (2026-10-18 America/Chicago). Baseline:
`e9eb6fdccbd300aeb08577789b55c2023939641c`; the existing `working-AI` tag is present
and unmodified. The owner authorizes actual replacement; this is implementation,
not a new proposal. Default packaged profile remains legacy until release gates
below pass. A separate Windows candidate build exercises the new pipeline.

## Preserved obligations and replacement boundary

Fixed: authenticated `/v1/tag-image`, pairing/grants/filesystem behavior,
explicit Generate Tags, independent append-only evidence, user data, JoyTag's
exact weights/vocabulary/preprocessing/threshold/top-k/settings activation.
Constrained: CPU-only ONNX, one heavyweight session at a time, one child per job,
105-second job timeout, 1.5 MB preview and 12 MP decode limits. Fluid: non-JoyTag
adapters, static model manifests, export/build recipes and source-to-category
mapping. No redesign or model marketplace. Source-installed evaluation opts in
with `ATLAS_TAGGING_PROFILE=rich`; a frozen engine reads its embedded profile and
ignores that environment override. HTTP callers cannot supply model paths,
install code, download models or change the active profile.

RAM++'s advertised smaller all-operator INT8 export
`anakhiu/ram-plus-onnx-int8@f5226bd4d7667a08fe475b95dcf0be66c86aa4fb` failed
ORT 1.20.1 CPU session creation: unsupported `ConvInteger`. FP32 ran but peaked
around 3.1 GB on the initial full-resolution living-room probe. Atlas instead
quantizes only MatMul; floating convolutions remain supported. Do not use the
incompatible export or silently upgrade the runtime to claim success.

MiVOLO's stock legacy ONNX export failed at `col2im`. The build-only symbolic
constructs ONNX's shape tensor explicitly. Learned architecture/weights are
unchanged. Three independent eager/ONNX head checks passed with maximum absolute
errors 0.00002324, 0.00021499 and 0.00021781. These checks establish numerical
export compatibility, not age accuracy.

RAM++ source and MiVOLO declare Apache-2.0. **The associated detector is AGPL-3.0.**
This does not solve Atlas's existing proprietary/commercial distribution gate.
See `packaging/TAGGING_MODEL_NOTICES.md`, upstream references and bundled license
texts. A proprietary ship decision still requires compatible rights/terms or a
qualified alternative detector; never describe this full pipeline as Apache-only.

## Implemented behavior and evidence

- `rich_tags.py`: RGB squash to 384x384, bilinear, ImageNet normalization,
  independent sigmoid over 4,585 logits and original per-label thresholds.
  Strict `>` preserves disabled threshold-1 labels. No top-k cap or tag padding.
  Every score/logit/threshold is retained, alongside qualified visible suggestions.
- `people_tags.py`: class-aware NMS for person/face detections, inverse letterbox
  coordinates in preview pixels, unique face containment and explicit ambiguity.
  Body-only and nonoverlapping face-only subjects remain possible; ambiguous
  matches are never guessed or counted a second time. Every retained detection
  has a confidence and bounding box. Subject IDs exist only within a run.
- Detector session ends before MiVOLO loads. Classification is sequential,
  batch-one, maximum 64 subjects; remaining records explicitly say resource-limit.
  Tiny or ambiguous subjects keep unknown attributes. No identities or family
  relationships. Actual crowd counting and occlusion quality remain unqualified.
- Configurable authenticated request `people_policy`: `adult_age` (default 18),
  `age_boundary_margin` (default 4 years), `appearance_min_score` (default .8).
  Invalid/NaN/bool/out-of-range values fail. Age margin is an abstention policy,
  **not a calibrated confidence interval**. Age <14 is child, age >=22 adult under
  defaults; the boundary band stays unknown. Scores are model scores, not verified
  personal characteristics. Raw age head and both appearance probabilities survive
  abstention. Aggregation reconciles adult + child + unknown to total people.
- Count strings derive from structured records, with `score: null` rather than
  invented confidence for a count. Animal/clothing/scene tags come from RAM++;
  this face/person detector does not produce instance counts for animals.
- `tag_provenance.py` now retains person counts (also fixing the legacy omission),
  detections/association, raw head records, aggregation policy, model components,
  full RAM++ predictions and warnings. Existing JSONL is never rewritten. Human
  data stores are untouched. Display deduplication preserves contributors.
- Extension generation uses a new companion's `people_source` announcement to
  run Things then People once. Older companions keep the shared Things/People
  pass. Existing Faces selection aliases the new people estimator in the rich
  profile, without a duplicate pass. Layout and JoyTag activation are unchanged.
  New `people` records survive per-image run storage and recovery.

## Actual source benchmark

`docs/evidence/rich-tagging-benchmark-2026-10-19.json` includes source-photo URLs,
original image hashes, preview dimensions, exact models, run IDs, output tags,
people records, timings and per-process peak working sets. No photos/weights are
committed. All six source photos are evaluated with legacy and rich profiles,
including JoyTag in both profiles through explicit benchmark requests.

| Photo | Legacy Things tags | RAM++ tags | Legacy people | New people |
| --- | ---: | ---: | ---: | ---: |
| Living room + dog | 5 | 16 | 0 | 0 |
| Winter market | 2 | 14 | 9 | 6 |
| Bus / street | 2 | 11 | 3 | 4 |
| Two coaches | 2 | 14 | 2 | 2 |
| Astronaut portrait | 1 | 13 | 2 | 1 |
| Cat close-up | 1 | 6 | 0 | 0 |

Reviewed count targets exist for five photos (0,4,2,1,0); all five new counts
match, versus two legacy count errors. The crowded market is **not ground-truth
annotated**, so neither count is reported as correct. This tiny convenience set
is not a representative accuracy benchmark. RAM++ returned 74 qualified tags
versus 13 legacy Things tags in total. It produces useful detail and also false
or overly contextual tags: `referee` in the coaches photo is a concrete example.
No semantic precision/recall rate is claimed. No verified ages or annotated
appearance labels exist here, so demographic error rates are NOT_MEASURED.
Children, broader occlusions, difficult lighting and real owner images remain
required qualification work.

RAM++ cold process runs including integrity checking: 3.95–4.18 seconds;
peak working set approximately 1.50–1.63 GiB. People pipeline: 3.45–7.93 seconds,
approximately .61 GiB. These are AMD EPYC host measurements, not laptop promises.
Rich assets total 1,260,911,310 bytes; retaining the entire old rollback/JoyTag
bundle totals 1,642,827,985 bytes before engine/native packaging. No hard RAM
ceiling is claimed. Full raw RAM++ evidence is roughly 0.6 MB per run; existing
JSONL-to-current projection still scales with current items, and browser run
history grows. Large-library indexing/retention remains a separate limitation.

**JoyTag:** identical suggestions and confidence scores in all six before/after
comparisons. A regression test fingerprints the untouched JoyTag branch and
checks its unchanged model/vocabulary hashes. Optional settings behavior is not
relaxed; direct explicit benchmark/API calls are not UI activation.
