# Windows port — native read-boundary foundation

Linux installer/recovery delivery is committed separately at `fbc2fd3`. Owner next requested Windows using the existing files. This first Windows increment reuses the ATLAS portable relative-path/read/list and stable-root identity contracts; it does not copy Chute source or substitute Linux runtime claims for Windows evidence.

`src/atlas_companion/windows_provider.py` implements a real Windows kernel **read-only** local-drive provider: held root/directory handles, single-component relative `NtCreateFile` with `OBJ_DONT_REPARSE`/`FILE_OPEN_REPARSE_POINT`, reparse rejection, volume/128-bit file IDs, bounded handle-based directory enumeration and preview bytes with source-change checks. Held handles deny delete sharing to resist reparenting. Protected native directories/files are checked by identity, including aliases; regular hardlinks are conservatively denied. Ambiguous DOS names, streams, traversal, UNC/device/extended namespaces and unsupported platforms are explicitly denied.

This is deliberately **not enabled in the integrated companion**. Windows user-private state DACLs, durable grant identity mapping, mutation semantics, per-user native registration/installer, bundled runtime, management and process recovery must be implemented and verified before enabling the Windows helper. Merely deleting `require_platform` or replacing Linux handles with resolved strings is forbidden.

`.github/workflows/windows-boundary.yml` runs the independent Windows kernel tests on an actual Windows runner when this source is pushed. Tests exercise real bytes/empty files/root identity, native ABI layout, junction denial, private aliases and root reparenting. Local Linux runs exercise three grammar/fail-closed checks and **skip all five Windows kernel tests**; that is not a Windows PASS. Check the actual workflow result before relying on the provider.

Next steps: first resolve every Windows kernel test failure and record exact runner/version/results; then implement protected per-user DACL state and root revocation, relative-handle no-overwrite writes/trash/idempotency, HKCU Native Messaging installation and Windows process-incarnation recovery. Use the existing Linux graph/HTTP/native protocol and reconstruction contracts as semantic fixtures. Preserve separate independent Linux/Windows evidence, revocation and `OUTCOME_UNKNOWN` behavior. A complete downloadable Windows installer has not been produced by this increment.
